# TypeScript Standards

This document establishes the type safety standards and TypeScript conventions for the codebase.

---

## 1. Strict Typing Principles

The project compiles under TypeScript strict mode (`strict: true`).

1. **Zero `any` Policy:**
   - The `any` type is forbidden across the codebase.
   - If a payload shape is uncertain (e.g. external webhook payload or dynamic third-party response), type it as `unknown` and narrow it using type guards or Zod schemas before consumption.
2. **Explicit API Contracts:**
   - Every API client function and Server Action must explicitly declare its parameter types and return type:
     ```ts
     export async function fetchDirectoryItems(
       params: GetDirectoryParams
     ): Promise<PaginatedResponse<DirectoryItem>> {
       // ...
     }
     ```
3. **No Unsafe Type Assertions:**
   - Avoid double casting (e.g. `x as unknown as TargetType`).
   - Validate and parse runtime inputs rather than forcing the compiler to accept unverified shapes.

---

## 2. Type Organization

- **Shared Domain Models:** Place cross-cutting global types (e.g. `User`, `Pagination`, `ApiResponse`, `SeoProps`) in `src/types/`.
- **Feature-Specific Types:** Place module-scoped types in `src/features/<feature>/types.ts`.
- **Next.js Route Types:** Use the built-in route type signatures or `PageProps` / `LayoutProps` generated by Next.js in `.next/types/routes.d.ts`.
- **Type-Only Imports:** Use `import type { ... }` when importing interfaces or type aliases to enable clean bundler tree-shaking.
